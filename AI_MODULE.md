# AI-модуль — принцип работы

## 1. Тип модели

Используется **многослойный персептрон** (MLP — Multilayer Perceptron) — нейронная сеть из библиотеки scikit-learn (`MLPClassifier`).

**Архитектура:**
```
Входной слой:    6 нейронов (признаки запчасти)
                 ↓
Скрытый слой 1: 128 нейронов (ReLU)
                 ↓
Скрытый слой 2:  64 нейрона  (ReLU)
                 ↓
Скрытый слой 3:  32 нейрона  (ReLU)
                 ↓
Выходной слой:   3 нейрона  (ok / warning / critical)
```

Это задача **классификации** — нейросеть определяет уровень критичности запаса каждой запчасти на складе.

## 2. Подготовка данных

**Проблема:** при первом запуске база данных пустая — нейросети не на чём обучаться.

**Решение — синтетический датасет** (`backend/app/ml/data_generator.py`): генерируется **2000 реалистичных примеров** поведения склада автосервиса.

### Признаки (входной вектор — 6 чисел на каждую запчасть)

| Признак | Описание |
|---|---|
| `current_stock` | Текущий остаток на складе (шт) |
| `min_stock` | Минимальный порог запаса (шт) |
| `daily_rate` | Средний дневной расход за 30 дней |
| `stock_ratio` | Отношение current / min (заполненность склада) |
| `days_until_stockout` | Расчётных дней до полного опустошения |
| `monthly_consumption` | Суммарный расход за 30 дней |

### Сценарии генерации

Для реалистичности применяется комбинация двух случайных параметров:

**Наполнение склада (5 сценариев):**
- `empty` (10%) — запас = 0
- `critical` (15%) — запас ниже 1/3 минимума
- `low` (20%) — запас между 1/3 и минимумом
- `normal` (35%) — запас в норме
- `full` (20%) — запас превышает минимум в 2–4 раза

**Скорость расхода (4 типа):**
- `fast` (15%) — быстрые запчасти (3–10 шт/день)
- `medium` (35%) — средние (0.5–3 шт/день)
- `slow` (35%) — медленные (0.05–0.5 шт/день)
- `idle` (15%) — почти не используются (< 0.05 шт/день)

### Правило разметки меток

Метка `urgency` назначается детерминированным правилом:

```python
if current == 0 or days < 7:   → critical
if days < 14 or current < min: → warning
else:                           → ok
```

## 3. Обучение

Запускается кнопкой "Запустить обучение" в интерфейсе → `POST /api/ai/train` (только admin).

**Файл:** `backend/app/ml/trainer.py`

**Процесс:**
1. Генерируется синтетический датасет (2000 примеров)
2. Из БД читаются реальные данные о расходе запчастей — если они есть, **добавляются к синтетике** (не заменяют, а дополняют)
3. Данные нормализуются через `StandardScaler` — все признаки приводятся к одному масштабу
4. Разбивка: **80% — обучение, 20% — тест**
5. Обучение с `adam`-оптимизатором, до 500 итераций, с ранней остановкой (`early_stopping=True`)
6. Модель и нормализатор **сохраняются на диск:**
   - `backend/app/ml/weights/model.pkl` — веса нейросети
   - `backend/app/ml/weights/scaler.pkl` — параметры нормализации

> **Важно:** нормализатор сохраняется вместе с моделью, потому что при инференсе реальные данные из БД должны быть нормализованы **теми же параметрами**, что и при обучении. Иначе предсказания будут неверными.

## 4. Метрики качества

После обучения возвращаются метрики по каждому классу:

| Метрика | Описание |
|---|---|
| **Accuracy** | Доля правильных ответов на тестовой выборке (общая) |
| **Precision** | Из всех, что модель назвала "critical", сколько действительно critical |
| **Recall** | Из всех реально critical — сколько модель нашла |
| **F1-score** | Гармоническое среднее Precision и Recall |
| **Support** | Количество примеров данного класса в тестовой выборке |

Пример ответа от API:

```json
{
  "status": "trained",
  "accuracy": 97.25,
  "samples_total": 2015,
  "real_samples": 15,
  "iterations": 143,
  "layers": [128, 64, 32],
  "metrics_by_class": {
    "ok":       { "precision": 0.98, "recall": 0.99, "f1_score": 0.98, "support": 240 },
    "warning":  { "precision": 0.96, "recall": 0.95, "f1_score": 0.95, "support": 88  },
    "critical": { "precision": 0.99, "recall": 0.97, "f1_score": 0.98, "support": 72  }
  }
}
```

Все метрики отображаются в интерфейсе на вкладке **"Обучение"**.

## 5. Инференс (предсказание по реальным данным)

При запросе `GET /api/ai/stock/analysis`:

1. **Сервис** (`ai_service.py`) читает все запчасти из таблицы `parts`
2. Для каждой запчасти суммирует расход за последние **30 дней** из таблицы `stock_operations` (операции типа `OUT`)
3. Формирует вектор из 6 признаков для каждой запчасти
4. **Предиктор** (`predictor.py`) загружает `model.pkl` + `scaler.pkl` с диска
5. Нормализует данные тем же `scaler`-ом, что использовался при обучении
6. Нейросеть возвращает:
   - `predict()` — предсказанный класс (ok / warning / critical)
   - `predict_proba()` — вероятности всех трёх классов
7. Вероятность предсказанного класса = **уверенность модели** (в %)
8. По формуле рассчитывается `recommended_order_qty` — покрыть расход на **45 дней вперёд**

Результат сортируется: `critical → warning → ok`.

## 6. Поток данных (сквозная схема)

```
PostgreSQL
(таблица parts + stock_operations за 30 дней)
          ↓
    ai_service.py
    формирует вектор признаков [6 чисел × N запчастей]
          ↓
    predictor.py
    ├── scaler.pkl → нормализация
    └── model.pkl  → predict + predict_proba
          ↓
    urgency + confidence% + recommended_order_qty
          ↓
    FastAPI → JSON-ответ
          ↓
    Фронтенд (AiPage.tsx)
    таблица с цветными бейджами, прогресс-барами и текстовыми пояснениями
```

## 7. Что видит пользователь

### Вкладка "Анализ склада"
Таблица всех запчастей с:
- Цветным бейджем статуса (красный — критично, жёлтый — внимание, зелёный — норма)
- Суточным расходом и расчётным числом дней до опустошения
- Прогресс-баром уверенности нейросети (%)
- Текстовым пояснением на русском:
  - `critical` → "Запас заканчивается через X дней, требуется срочный заказ"
  - `warning` → "Запас ниже нормы, рекомендуется пополнить"
  - `ok` → "Запас в норме"

### Вкладка "Рекомендации к закупке"
Только те позиции, по которым нейросеть рекомендует закупку (`recommended_order_qty > 0`), с расчётной стоимостью в рублях и общей суммой.

### Вкладка "Обучение" (только администратор)
- Информация об архитектуре модели: `MLP: 6 → 128 → 64 → 32 → 3`
- Кнопка "Запустить обучение"
- После обучения — карточки с Accuracy, числом итераций, объёмом выборки
- Таблица метрик по классам: Precision / Recall / F1 / Support

## 8. Соответствие требованиям ТЗ

| Требование | Реализация |
|---|---|
| Выбрать тип модели | MLPClassifier — многослойный персептрон (нейронная сеть) |
| Подготовить данные | 2000 синтетических примеров (`data_generator.py`) + реальные из БД (`stock_operations`) |
| Метрики качества | Accuracy, Precision, Recall, F1 по каждому из трёх классов |
| API endpoint | `GET /api/ai/stock/analysis`, `GET /api/ai/stock/reorder`, `POST /api/ai/train` |
| Сохранение модели | `model.pkl` + `scaler.pkl` через `joblib`, загружаются при каждом запросе |
| Отображение результата | AiPage с 3 вкладками, цветовые бейджи, пояснения на русском, прогресс-бары уверенности |
