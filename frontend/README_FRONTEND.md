## 1. Что это за приложение

**АвтоСервис** — веб-приложение для автоматизации работы станции технического обслуживания (СТО). Предназначено для механиков и администраторов.

### Что умеет приложение:

| Раздел | Функционал |
|---|---|
| **Дашборд** | Сводная статистика: выручка, активные заказы, количество авто и запчастей |
| **Заказы** | Создание, просмотр, редактирование заказ-нарядов; смена статусов; шаблоны услуг |
| **Склад** | Учёт запчастей, резервирование, рекомендации к дозаказу |
| **Автомобили** | База клиентских авто, история ТО каждого автомобиля |
| **Профиль** | Информация о текущем пользователе, выход из системы |

## 2. Стек технологий и зачем каждый

### React 18 + TypeScript
**React** — библиотека для построения пользовательского интерфейса. Вместо того чтобы вручную обновлять HTML, мы описываем как должен выглядеть экран, а React сам обновляет только изменившиеся части.

**TypeScript** — надстройка над JavaScript с типами. Позволяет поймать ошибки ещё до запуска кода: например, если передаёшь строку туда, где ожидается число — редактор сразу подсветит.

### React Router v7
Библиотека для навигации между страницами без перезагрузки браузера. Пользователь переходит с `/orders` на `/vehicles` — страница не перезагружается, просто меняется компонент внутри.

### Tailwind CSS v4
CSS-фреймворк "утилитарного" подхода. Вместо написания отдельных CSS-файлов, стили пишутся прямо в HTML через классы:
```html
<!-- Обычный CSS -->
<div class="card">...</div>
.card { background: #1e293b; border-radius: 12px; padding: 20px; }

<!-- Tailwind -->
<div class="bg-slate-900 rounded-xl p-5">...</div>
```
Итог: нет отдельных CSS-файлов для компонентов, стили читаются сразу в разметке.

### Lucide React
Библиотека SVG-иконок. Используется везде в интерфейсе (`Bell`, `Wrench`, `Car`, `Package` и т.д.).

### Vite
Инструмент сборки — запускает dev-сервер и собирает итоговый бандл для продакшена. Работает намного быстрее устаревшего Webpack.

### React Context API
Встроенный в React механизм для хранения глобального состояния приложения. Позволяет любому компоненту получить доступ к данным (заказы, запчасти, авто) без "прокидывания пропсов" через все уровни дерева.

## 3. Как запустить

**Требования:** Node.js версии 18 или выше.

```bash
# 1. Перейти в папку проекта
cd caas

# 2. Установить зависимости (только первый раз)
npm install

# 3. Запустить dev-сервер
npm run dev
```

Приложение откроется на: **http://localhost:5173**

**Авторизация подключена к бэкенду.** Войти можно через `POST /api/auth/login`. Дефолтные учётки: логин `admin`, пароль `admin123`.

### Сборка для продакшена

```bash
npm run build
```

Готовые файлы появятся в папке `dist/` — их можно положить на любой статический хостинг (Nginx, Vercel, GitHub Pages).

### Как страница получает данные

Каждая страница вызывает хук `useApp()` и получает нужные данные и функции:

```tsx
// Пример из OrdersPage
const { orders, addOrder, updateOrderStatus, deleteOrder } = useApp();
```

Никакой "прокидки пропсов" через промежуточные компоненты — любая страница обращается напрямую к контексту.

## 6. Глобальное состояние — AppContext

**Файл:** `src/app/context/AppContext.tsx`

Это центр всего приложения. Здесь хранятся три массива данных и функции для их изменения.

### Что хранится

```typescript
parts    — массив запчастей на складе
orders   — массив заказов
vehicles — массив автомобилей
```

### Типы данных

#### Part (запчасть)
```typescript
{
  id: string
  name: string          // название: "Моторное масло 5W-30"
  sku: string           // артикул: "OIL-5W30-001"
  category: string      // категория: "Жидкости"
  quantity: number      // физический остаток на складе: 15
  reserved: number      // зарезервировано под активные заказы: 4
  minStock: number      // минимальный остаток для оповещения: 20
  unitPrice: number     // цена за штуку: 850
  supplier: string      // поставщик
  location: string      // ячейка на складе: "А-01"
  lastRestocked: string // дата последнего пополнения
}
```

#### Order (заказ)
```typescript
{
  id: string
  orderNumber: string      // "ORD-001"
  customer: string         // имя клиента
  phone: string            // телефон клиента
  vehicleId?: string       // ID авто из базы (если есть)
  vehicle: string          // текстовое описание авто
  licensePlate: string     // гос. номер
  services: string[]       // список услуг: ["Замена масла", "Ротация шин"]
  parts: OrderPart[]       // используемые запчасти
  status: OrderStatus      // "В ожидании" | "В работе" | "Завершён" | "Отменён"
  createdDate: string
  completedDate?: string
  totalAmount: number      // итоговая сумма
  laborCost: number        // стоимость работ
  assignedTo?: string      // назначенный мастер
}
```

#### Vehicle (автомобиль)
```typescript
{
  id: string
  make: string          // марка: "Toyota"
  model: string         // модель: "Camry"
  year: number          // год: 2020
  licensePlate: string  // гос. номер
  vin: string           // VIN-номер
  owner: string         // владелец
  ownerPhone: string
  color: string
  mileage: number       // пробег
  lastService: string   // дата последнего ТО
  nextService: string   // дата следующего ТО
  serviceRecords: ServiceRecord[]  // история обслуживания
}
```

### Доступные функции

```typescript
// Запчасти
addPart(data)              — добавить запчасть
updatePart(id, data)       — редактировать запчасть
deletePart(id)             — удалить запчасть

// Заказы
addOrder(data)             — создать заказ
updateOrder(id, data)      — редактировать заказ
updateOrderStatus(id, st)  — сменить статус (с бизнес-логикой!)
deleteOrder(id)            — удалить заказ

// Автомобили
addVehicle(data)           — добавить авто
updateVehicle(id, data)    — редактировать авто
deleteVehicle(id)          — удалить авто
```

## 7. Авторизация

**Файл:** `src/app/auth/session.ts`

Авторизация построена на `localStorage` браузера — данные пользователя сохраняются и остаются после закрытия вкладки.

### Как работает

1. Пользователь вводит логин/пароль на `LoginPage`
2. Данные сохраняются в `localStorage` под ключом `sto.auth.user`
3. При каждом переходе на защищённую страницу — роутер проверяет наличие данных
4. Если данных нет — редирект на `/login`
5. При выходе — `clearAuthUser()` удаляет запись из `localStorage`

### Защита маршрутов

```typescript
// routes.tsx — loader проверяет авторизацию перед каждой страницей
{
  path: '/',
  Component: Layout,
  loader: () => {
    if (!getAuthUser()) return redirect('/login'); // не авторизован → на логин
    return null;
  },
}
```

### При подключении бэкенда

`session.ts` уже обновлён — добавлена функция `setAuthSession(token, user)`, которая сохраняет JWT-токен рядом с данными пользователя. `LoginPage` уже делает реальный запрос к `POST /api/auth/login`.

## 9. Страницы и что на них происходит

### LoginPage — Страница входа

Форма с полями логин и пароль. При отправке:
- Делает `POST /api/auth/login` → получает JWT-токен
- Делает `GET /api/auth/me` → получает `full_name`
- Сохраняет токен и данные пользователя в `localStorage`
- Редиректит на дашборд

---

### DashboardPage — Дашборд

Показывает 4 карточки с ключевыми метриками и таблицу последних заказов. Все данные берёт из `useApp()` и вычисляет на лету:

```typescript
// Выручка = сумма totalAmount всех завершённых заказов
const totalRevenue = orders
  .filter(o => o.status === 'Завершён')
  .reduce((sum, o) => sum + o.totalAmount, 0);

// Активные заказы = "В работе" + "В ожидании"
const activeOrders = orders.filter(
  o => o.status === 'В работе' || o.status === 'В ожидании'
).length;
```

### OrdersPage — Управление заказами

Самая сложная страница. Состоит из нескольких внутренних компонентов:

#### PartsSelector
Компонент выбора запчастей при создании/редактировании заказа:
- Поиск запчастей по названию или артикулу
- Показывает доступное количество (`quantity - reserved`)
- Предупреждает если выбранное количество превышает доступное
- Позволяет менять количество прямо в таблице

#### NewOrderForm / EditOrderModal
Форма создания/редактирования заказа. Разбита на секции:
1. **Клиент** — ФИО, телефон
2. **Автомобиль** — выбор из базы или ввод вручную
3. **Услуги** — шаблоны услуг (11 вариантов) или ввод вручную
4. **Запчасти** — через `PartsSelector`
5. **Стоимость** — стоимость работ вводится вручную, запчасти и итог считаются автоматически
6. **Мастер** — ФИО мастера

#### OrderDetailModal
Модальное окно просмотра заказа:
- Полная информация о заказе
- Таблица запчастей с суммами
- Кнопки смены статуса (зависят от текущего статуса)
- При нажатии "Завершить" — показывает список запчастей которые будут списаны

#### Статус-фильтры
Вкладки в верхней части страницы фильтруют заказы по статусу. Счётчик в каждой вкладке обновляется в реальном времени.

### VehiclesPage — База автомобилей

#### Список автомобилей
Карточки с кратким описанием. Кнопки: просмотр, редактировать, удалить.

#### VehicleDetailModal
Открывается при клике на карточку или кнопку просмотра. Две вкладки:

**Информация** — все поля автомобиля и владельца.

**История ТО** — список всех сервисных записей. Каждая запись содержит:
- Дата и номер заказа
- Список выполненных услуг (тегами)
- Список использованных запчастей с ценами
- Итоговая стоимость
- Мастер

История ТО заполняется **автоматически** — когда заказ переводится в статус "Завершён", запись добавляется сама.

#### EditVehicleModal
Форма редактирования — предзаполнена текущими данными авто.

### PartsPage — Склад запчастей

#### Статистика (4 карточки)
- Всего позиций
- Позиции с низким остатком
- Общая стоимость склада
- Суммарное количество единиц

#### Предупреждение о низком остатке
Красный баннер появляется автоматически если хотя бы одна позиция ниже минимума.

#### Рекомендации к дозаказу
Блок с позициями сгруппированными по поставщику. Для каждой позиции считается рекомендуемое количество к заказу:
```typescript
// дефицит + буфер = минимальный остаток
const toOrder = item.minStock - item.quantity + item.minStock;
```
Кнопка "Сформировать заявку" показывает список для конкретного поставщика.

#### Таблица запчастей
Колонка **"Доступно"** = `quantity - reserved`. Если запчасть зарезервирована — показывает "Резерв: X". Если доступно 0 или меньше — подсвечивает красным.

#### Мини-индикатор остатка
У каждой позиции есть маленькая цветная полоска — зелёная если всё хорошо, красная если ниже минимума.

## 11. Ключевая бизнес-логика

### Резервирование запчастей

Это главная логика приложения. Реализована в `AppContext.tsx` в функции `updateOrderStatus`.

**Проблема:** нельзя просто списывать запчасти сразу при создании заказа — заказ может быть отменён. Но и показывать их как "доступные" нельзя — другой заказ может их забрать.

**Решение:** двухступенчатый учёт:
- `quantity` — физический остаток (сколько реально есть на складе)
- `reserved` — зарезервировано под активные заказы
- `available = quantity - reserved` — сколько можно взять

```
┌─────────────────────────────────────────────────────────┐
│                  ЖИЗНЕННЫЙ ЦИКЛ ЗАКАЗА                   │
│                                                          │
│  Создан          В работе        Завершён                │
│  (В ожидании)  ──────────────►  (запчасти списываются)   │
│       │                          reserved -= qty         │
│       │         reserved         quantity -= qty         │
│       └───────► += qty                                   │
│                                                          │
│  Создан          Отменён                                 │
│  (В работе)  ──► reserved -= qty  (возврат резерва)      │
└─────────────────────────────────────────────────────────┘
```

**Код в `updateOrderStatus`:**

```typescript
// "В ожидании" → "В работе": резервируем запчасти
if (newStatus === 'В работе' && oldStatus === 'В ожидании') {
  setParts(prev => prev.map(part => {
    const op = order.parts.find(p => p.partId === part.id);
    return op ? { ...part, reserved: part.reserved + op.quantity } : part;
  }));
}

// "В работе" → "Завершён": списываем со склада и снимаем резерв
else if (newStatus === 'Завершён' && oldStatus === 'В работе') {
  setParts(prev => prev.map(part => {
    const op = order.parts.find(p => p.partId === part.id);
    return op ? {
      ...part,
      quantity: part.quantity - op.quantity,  // физическое списание
      reserved: part.reserved - op.quantity,  // снятие резерва
    } : part;
  }));
  // + автоматически создаётся запись в истории ТО автомобиля
}

// "В работе" → "Отменён": только снимаем резерв
else if (newStatus === 'Отменён' && oldStatus === 'В работе') {
  setParts(prev => prev.map(part => {
    const op = order.parts.find(p => p.partId === part.id);
    return op ? { ...part, reserved: part.reserved - op.quantity } : part;
  }));
}
```

### Автоматическая история ТО

При завершении заказа — если к заказу привязан автомобиль (`vehicleId`) — автоматически создаётся `ServiceRecord` и добавляется в историю автомобиля:

```typescript
const record: ServiceRecord = {
  date: today,
  orderNumber: order.orderNumber,
  services: order.services,
  parts: order.parts.map(op => ({ name: op.partName, quantity: op.quantity, unitPrice: op.unitPrice })),
  totalCost: order.totalAmount,
  mechanic: order.assignedTo,
};
setVehicles(prev => prev.map(v =>
  v.id === order.vehicleId
    ? { ...v, lastService: today, serviceRecords: [record, ...v.serviceRecords] }
    : v
));
```

- Подставляются запчасти по умолчанию для этой услуги
